## 权限与安全结论

| 角色或条件 | 上传/对象存储拉取/构建/导入/推送 | 清理原始制品 | 部署 | 服务端保证 |
| --- | --- | --- | --- | --- |
| 全局管理员 | 可在已授权项目操作；存储配置另受管理员约束 | 可 | 可 | 项目权限、Endpoint 权限与 registry 权限取交集 |
| 项目管理员 | 可在所属项目操作 | 可 | 可 | 同上；清理额外检查任务与 Release/快照引用 |
| 开发者 | 仅项目制品写权限允许的操作 | 不可 | 按项目发布权限 | Docker/registry/发布仍必须通过 Endpoint 权限交集 |
| 观察者 | 不可写入或触发任务 | 不可 | 不可 | 直接 API 仍被拒绝，前端禁用不是授权边界 |
| 缺少 Endpoint 权限的用户 | 不可触发 Docker、registry 或部署动作 | 不适用 | 不可 | 后端拒绝，即使前端入口可见也不能绕过 |

所有配置、制品和发布动作均使用服务端鉴权。敏感配置继续加密保存；对象存储/registry 凭据仅在 adapter 内使用。API 响应、审计、错误和前端只展示字段名、受限 ID、类型、SHA256、状态、tag、digest 或脱敏 reason，不展示 access key、secret key、签名 URL、服务器真实路径或原始制品内容。

## 真实环境演练清单

当前工作区没有运行在 `8999`/`9000` 的前后端服务，也没有可用于本轮的 Docker daemon、MinIO/S3、私有 registry、真实 Endpoint 权限用户或浏览器多角色会话。因此没有把 fake adapter 的成功误记为真实部署成功；以下演练在部署环境完成后应回填结果。

1. 使用管理员在 Portainer 中预配置 S3 Compatible 存储与 registry，确认配置读取、错误和审计均不回显凭据；从受限对象键拉取一个 Jar、dist ZIP、Docker tar 和 OCI archive，并验证最终 SHA256。
2. 对上述四类制品分别完成「获取/上传 → 安全校验 → 导入或受控包装 → 推送 → 选择 `ready` 制品 → 发布」；确认最终 Artifact 记录原始 SHA256、来源、tag、digest 和强追溯。
3. 分别注入 hash 不匹配、恶意 archive、Docker build/load 中断、registry 认证/TLS/网络失败、远端 tag 冲突、端口冲突和健康检查失败；确认无临时文件或候选镜像残留，当前线上 Release 保持不变。
4. 用管理员、项目管理员、开发者、观察者及无 Endpoint 权限用户检查上传、拉取、构建、推送、清理和发布；确认前端入口与服务端 403/拒绝行为一致。
5. 检查浅色、深色和高对比主题；长文件名、SHA256、tag/digest、失败 reason 和中英文文案不得溢出。确认 SPA fallback、MPA 真正 404、三档缓存和可选 404 页面符合受控 dist 模板。
6. 在存在历史 Release、回滚快照或进行中制品任务时尝试清理；必须被阻断。对可清理制品验证只删除平台本地原始副本，Artifact、Release、SHA256、最终 tag/digest 和审计事实仍可查询；不得删除用户管理的远端 S3 对象。
