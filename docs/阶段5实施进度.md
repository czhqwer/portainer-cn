## 2. 基线审计

- `PlatformEnvironment.Targets` 已具备 `EndpointID`、`NodeName`、`HostAddress`、角色与启用状态；现有 `single` 选择器只返回第一个 workload，不能用于多主机。
- `PlatformRelease` 已预留 `TargetResults`，但没有目标组、批次策略、不可变多目标快照或逐 target 锁；`SingleTargetExecutor` 在正式切换后把单个 runtime 写入全局 `RuntimeSnapshot`。
- 阶段 4 `GatewayReleaseCutover` 已严格使用环境 `HostAddress` 与已成功 Release 的 published host port，不访问容器内部 IP；阶段 5 必须将其扩展为多个 upstream，不能退化为容器地址。
- 当前 `requireEndpointAccessForTargets` 只检查启用 workload target；multi 环境的创建、修改、预检和发布必须同时校验每个 workload 与唯一 gateway Endpoint 的授权交集。
- Portainer 通用 `EndpointGroup` 没有满足平台所需的不可变成员、顺序、发布快照与失败补偿语义，因此阶段 5 不复用它作为发布组。

## 3. 冻结契约

### 3.1 目标、组与快照

1. `single` 保持完全兼容：恰好一个启用 workload target；无 gateway 时延续阶段 1-3 发布路径。
2. `multi` 必须有至少一个启用 workload target，且恰好一个启用 gateway target。每个 workload target 必须有不可为空、不可为容器 IP 的 `HostAddress`，网关只访问该地址的 published port。
3. 工作负载 target 的稳定身份为 `EndpointID + NodeName + HostAddress + Role`；创建 Release 时按目标组的显式顺序快照。未指定组时按 `EndpointID`、`NodeName`、`HostAddress` 的稳定升序生成快照。
4. 新增平台专用 HostGroup 与 BatchPolicy。HostGroup 修改只影响未来 Release；Release 保存 immutable target/batch snapshot，历史记录和回滚不得读取当前可变组成员。

### 3.2 批次与状态机

1. BatchPolicy 包含 `BatchSize`、`IntervalSeconds`、`PauseOnFailure`、`RollbackSucceededTargets`；默认单 target 一批、失败暂停、恢复已切换 target。
2. 每个 `PlatformReleaseTargetResult` 只能依次处于 `pending → running → succeeded`，或进入 `failed`、`skipped`、`recovered`、`recovery-failed`。未开始 target 永远不能标记为成功。
3. “批次成功”只表示该批所有 target 已通过最终健康检查；只有全部批次成功且网关完成候选预检/reload 后，Release 才能为 `succeeded`。
4. 任一 target pull、candidate、switch、最终健康、网关切流或恢复失败时，停止后续批。已成功 target 按不可变运行快照恢复；恢复失败时 Release 进入人工处置状态。
5. Handler 事务只写状态、审计和短锁；Docker/Agent、网络预检、批间等待与网关 reload 一律在事务外执行。进程重启时 `running` target 必须按其 lease 被标记 interrupted 或进行受控恢复，不能假定成功。

### 3.3 连通性与网关

1. 发布前对每个 workload `HostAddress:publishedPort` 做 gateway→workload TCP/HTTP 预检，采用固定超时、有限并发和稳定 reason；原始网络错误只写服务端日志。
2. 网关 active upstream 集合仅由本次或历史 Release 中 `succeeded` 且未回滚的 TargetResult 生成；失败、未运行、已恢复 target 均不得进入集合。
3. 多 upstream 不实现 `weight`、灰度、自动扩缩容或多网关 HA。候选配置、`nginx -t`、原子激活、reload 和恢复沿用阶段 4 机制。
