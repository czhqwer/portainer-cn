# 需求评审结论

日期：2026-07-11
结论：Approve with minor changes
关联文档：[私有化微服务部署平台产品需求文档](./私有化微服务部署平台产品需求文档.md)、[阶段0平台核心模型与后端边界设计](./阶段0平台核心模型与后端边界设计.md)、[阶段1分批实施方案](./阶段1分批实施方案.md)

## 1. 总体结论

可以进入阶段 1，但必须按 Gate 拆分放行。

Gate 0A 文档与模型冻结通过，可以启动阶段 1 的模型、dataservice、CRUD API、异步发布状态机框架、Artifact image-reference、前端页面骨架和部署向导骨架。

Gate 0B 尚未通过。Docker 发布执行器、ContainerAdapter、RuntimeDriver 真实执行链路、candidate 容器验证、正式容器切换和旧容器恢复逻辑，必须等 Docker/Agent candidate 技术 Spike 完成并回填结论后再正式编码。

## 2. 可先行范围

- 平台核心模型：Project、Environment、Application、ServiceDefinition、ServiceDeployment、Artifact、Release、ReleaseStep、ReleaseLock。
- BoltDB dataservice、事务读写、Export/Import。
- `/api/platform` CRUD API。
- 所有平台业务接口的管理员访问限制。
- Artifact `image-reference` 登记和查询。
- Release 状态机、幂等键、发布锁、步骤记录和 validate API。
- 前端项目、应用、服务、制品、发布记录页面骨架。
- 应用部署向导骨架。

## 3. 暂缓范围

- Docker RuntimeDriver 正式编码。
- DeploymentExecutor / SingleTargetExecutor 正式编码。
- ContainerAdapter 正式编码。
- Docker candidate 容器启动、健康验证、停止和删除。
- 固定端口正式容器切换。
- 旧容器自动恢复和孤儿资源清理的真实 Docker 操作。
- 真实镜像拉取、digest 解析和私有镜像认证执行链路。

## 4. 残留问题处理

| 优先级 | 问题 | 处理结论 |
| --- | --- | --- |
| P1 | `RuntimeDriver.Switch` 接口仍携带 `candidate RuntimeRef`，容易误导实现为提升 candidate | 改为传入 `CandidateValidationSnapshot`，表达“candidate 已验证并清理后，基于验证摘要切换正式容器” |
| P1 | Release 字段表中 `LeaseOwner` 与 `LeaseExpiresAt` Markdown 行损坏 | 拆成两行，避免实现漏字段 |
| P1 | `PlatformHealthCheckResult` 被引用但未定义字段 | 补充 `Level`、`Type`、`Status`、`Target`、`StatusCode`、`ErrorMessage`、`StartedAt`、`FinishedAt`、`LogSummary` |
| P2 | ADR 权限口径仍写 V0.1 写操作限制管理员 | 改为 V0.1 所有 `/api/platform` 业务接口包括读取都限制管理员 |
| P2 | 成功发布字段清单少写 `CurrentArtifactID` / `CurrentImage` | 与事实来源规则统一为完整字段清单 |
| P2 | 设计稿对齐矩阵标题仍写 `PRD v1.2` | 改为 `PRD v1.3` |
| P2 | PRD “V0.1 开发前必须完成 Spike”表述过宽 | 收窄为 Docker 发布执行器正式编码前必须完成 |

## 5. 已闭合关键点

- `CurrentSuccessfulReleaseID` 已修正为 `CurrentServingReleaseID`。
- `recovery-failed` / `interrupted` 默认继续持锁，直到人工处理或恢复重试完成。
- candidate 不再与正式容器并行提供服务。
- V0.1 所有 `/api/platform` 业务接口限制管理员访问。
- `queued watchdog`、幂等 payload 校验、ReleaseLock、租约续期和人工处置接口已进入设计。
- 生产环境只允许 `verified`，不得静默降级到 `startup-only` 或 `unverified`。
- Gate 0A / Gate 0B 拆分已明确：模型、CRUD、异步框架和前端骨架可先行；Docker 执行链路等待 Spike。

## 6. 放行意见

允许进入阶段 1 的非 Docker 执行器开发。推荐先按以下顺序推进：

1. 文档基线与 CR 收口。
2. 后端核心模型与 dataservice。
3. 平台 CRUD API 与管理员权限。
4. Artifact 与 Release 控制平面。
5. 前端页面骨架与部署向导。

Docker RuntimeDriver、ContainerAdapter、DeploymentExecutor 和真实发布恢复链路必须等 Gate 0B 通过后再进入正式编码。
