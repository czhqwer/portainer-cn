## 2. 批次 1：基线审计与方案冻结

### 2.1 目标、范围与边界

本批只冻结阶段 2 的配置、安全、权限、审计和人工回滚边界；不改业务代码、不开放非管理员访问、不实现配置或回滚 API。

阶段 2 严禁提前实现以下能力：Jar、dist、镜像 tar 或 OCI archive 的构建/导入，MinIO/S3 制品拉取，向已有 registry 推送标准 tag，中心 Nginx、域名、证书或网关切流，多 Docker 主机或跨主机分批发布，以及 Kubernetes、Git、源码构建、内置 registry、完整 CI/CD、审批流。

敏感变量在后续批次中只能以受 Portainer 加密能力保护的密文保存；明文不得进入 BoltDB 非加密字段、日志、审计、错误响应、前端 toast 或测试快照。

### 2.3 冻结的数据与安全约束

- 配置集作用域固定为 `project`、`environment`、`service-deployment`；默认配置集名为 `default`。一个作用域的同名有效配置集必须唯一。
- 有效普通配置的覆盖顺序固定为：项目级 < 环境级 < 服务部署级 `EnvOverrides`。同名后层覆盖前层，输出和哈希必须使用稳定排序。
- 发布快照必须包含 `SpecRevision`、参与合并的 `ConfigSetRevisions`、脱敏后的 `Entries`、`ConfigHash` 与 `SecretSnapshots`。删除或修改现有配置不能改写历史 Release 快照。
- 敏感数据的 API 默认仅返回变量名、类型、是否有值、hash/版本和字段名；reveal/copy 单独鉴权且写入审计。`SecretSnapshots` 仅保存变量名、密钥版本、密文或可回滚引用和密文 hash。
- 配置漂移定义为当前有效配置 hash 或任一参与配置集 revision 与当前成功 Release 快照不一致；服务部署状态使用既有 `config-changed`，不覆盖 `runtime-missing` 等运行态漂移。
- 人工回滚必须从一个历史成功且可追溯的 Release 创建新的 `TriggerType=rollback` Release，并填写 `RollbackSourceReleaseID`。预检失败或执行失败不得改写现有 Release，也不得破坏当前运行版本。

### 2.4 API 契约草案

以下路径以既有 `/api/platform` 路由风格为基线；批次实现时仍需按现有 handler 的错误 envelope、资源版本和审计辅助函数落地。

| 批次 | 路径 | 目的 | 权限与脱敏要求 |
| --- | --- | --- | --- |
| 3 | `GET/POST /api/platform/config-sets` | 按项目、作用域、作用域 ID 查询或创建配置集 | 读取遵循项目查看权；写入要求项目管理员；响应不回传敏感明文/密文 |
| 3 | `GET/PUT/DELETE /api/platform/config-sets/{configSetId}` | 查询、更新或归档配置集 | 更新使用 `ResourceVersion`；内容变化递增 `Revision` |
| 3 | `GET /api/platform/service-deployments/{deploymentId}/effective-config` | 返回三级合并后的有效配置和 hash | 仅返回脱敏条目；服务部署不可见时按权限矩阵返回 404 |
| 4 | `POST /api/platform/config-sets/{configSetId}/entries/{key}/reveal` | 有权限地读取敏感值 | 全局管理员或项目管理员的显式 sensitive-reveal 权限；写 `secret.revealed` 审计；不得缓存或记录值 |
| 5 | `GET/PUT /api/platform/projects/{projectId}/members` | 读取或维护项目用户/团队角色 | 仅全局管理员可管理项目范围外资源；项目管理员仅能管理所属项目成员 |
| 6 | `GET /api/platform/audit-logs` | 按对象、操作者、action、result、时间范围筛选审计 | 审计摘要严格脱敏；`SensitiveFields` 只含字段名 |
| 7 | `POST /api/platform/releases/{releaseId}/rollback` | 预检并创建新的回滚 Release | 历史版本可回滚性、目标、配置/敏感快照、镜像与锁均须校验；生产环境必须二次确认 |
| 7 | `GET /api/platform/releases/{releaseId}/rollback-diff` | 返回当前版本与目标 Release 的镜像、配置、端口和变量摘要差异 | 敏感变量只能显示名称、是否有值、hash/版本，不显示值或密文 |

### 2.5 RBAC 与 Endpoint 权限冻结

| 能力 | 全局管理员 | 项目管理员 | 开发者 | 只读观察者 |
| --- | --- | --- | --- | --- |
| 查看项目、应用、服务、发布、状态和日志 | 允许 | 所属项目且有 Endpoint 访问权时允许运行态/日志 | 所属项目且有 Endpoint 访问权时允许运行态/日志 | 所属项目且有 Endpoint 访问权时允许运行态/日志 |
| 管理环境、应用、服务与普通配置 | 允许 | 所属项目 | 仅服务部署配置且具备明确授权 | 拒绝 |
| 创建发布与历史回滚 | 允许 | 所属项目且有 Endpoint 访问权 | 所属项目、明确授权且有 Endpoint 访问权 | 拒绝 |
| 查看敏感变量元数据 | 允许 | 所属项目 | 所属项目的脱敏元数据 | 所属项目的脱敏元数据 |
| reveal/copy 或修改敏感变量 | 允许 | 所属项目且具有敏感变量管理权限 | 拒绝 | 拒绝 |
| 查看项目审计 | 允许 | 所属项目 | 拒绝 | 拒绝 |

无对象可见权的读请求返回 404；已知对象的禁止操作返回 403。所有需要目标 Docker 环境的发布、回滚、状态和日志操作还必须通过 Portainer Endpoint 权限检查。

### 2.6 阶段 2 验收与风险清单

| 验收主题 | 最小证据 |
| --- | --- |
| 三级配置与漂移 | 三级同名变量覆盖、删除/修改后的稳定 hash、当前成功 Release 的 `config-changed` 标记测试 |
| 敏感变量 | API、日志、审计和测试快照的泄漏扫描；容器收到值而 API 默认脱敏的测试 |
| 权限 | 管理员、项目管理员、开发者、观察者、无 Endpoint 权限五类矩阵测试，以及直接访问 API 的服务端拒绝测试 |
| 审计 | 配置、安全、权限、denied、回滚写入及筛选测试；审计摘要和 `SensitiveFields` 脱敏断言 |
| 人工回滚 | v1/v2 成功发布后新建回滚 Release、镜像/端口/敏感快照校验失败保持 v2 可用的测试 |
| 前端验收 | 中英文、深浅主题、长变量/镜像/审计详情、权限禁用态和确认操作的手工记录 |
