## 已知基线差异

go test ./api/datastore -count=1 中的 TestMigrateData/migrate_version_24_to_latest 未通过，原因已复现：

- api/datastore/test_data/output_24_to_latest.json 为 CRLF，长度 28,972 字节。
- Windows 本轮 ExportJSON 生成 LF，长度 28,141 字节。
- 测试对原始 []byte 做比较，首个差异位于第一个换行符；阶段 6 未修改迁移器或该 fixture。

因此此项记录为仓库跨平台 fixture 基线差异，不作为阶段 6 功能通过证据；未修改 fixture 或迁移实现来掩盖差异。

## 安全与边界验收

- DatabaseConnection 仍是用户/Endpoint 级工作台连接，ContainerID 仅作兼容与自动填充；项目部署使用独立资源模型并以 Host/Port 直连。
- 数据库密码、密文和完整数据库 URL 不进入普通 API 响应、Release 快照、审计摘要或备份导出；仅在 Docker 候选容器创建的短生命周期内解密注入。
- 资源与绑定 API 校验项目角色、环境归属、Endpoint 权限；活跃绑定和历史 Release 快照会阻止资源归档。
- 容量 API 只聚合制品元数据；不扫描宿主机路径，对象存储剩余容量明确为 not-supported。
- 失败诊断只聚合稳定 reason，不返回外部系统的原始错误。

## 外部演练待办

本地未提供真实 MySQL/MariaDB、PostgreSQL、Redis、MinIO/S3/OSS、Docker/Agent 或生产 Endpoint，以下必须在部署环境补充，且不得以 fake 成功替代：

1. 使用最小权限临时账号执行三类数据库的创建、连接测试、绑定、发布变量注入和失败回滚验证。
2. 验证本地 Agent + 已发布端口场景仍使用 Host/Port，不依赖容器 WebSocket 代理。
3. 对目标 MinIO/OSS S3 Compatible endpoint 完成 TLS、prefix、List、Head、Download、超时和 SHA256 演练；若失败且需独立 OSS adapter，先由用户冻结范围。
4. 使用真实对象存储与制品数据确认容量汇总、阈值和稳定 failure reason 的可操作性。
