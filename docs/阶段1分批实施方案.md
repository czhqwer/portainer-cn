# 阶段1分批实施方案

版本：v1.0
日期：2026-07-11
关联文档：[私有化微服务部署平台产品需求文档](./私有化微服务部署平台产品需求文档.md)、[阶段0平台核心模型与后端边界设计](./阶段0平台核心模型与后端边界设计.md)、[功能优先级与工作量排期](./功能优先级与工作量排期.md)、[阶段1 Goal 模式提示词模板](./阶段1Goal模式提示词模板.md)

## 1. 总体结论

阶段 1 拆成 7 批实施。批次 1 到批次 5 属于 Gate 0A 已放行范围，可以先行开发；批次 6 到批次 7 依赖 Gate 0B Docker/Agent candidate 技术 Spike 结论，未通过前不得进入 Docker 发布执行器正式编码。

阶段 1 的目标仍是 V0.1 技术预览闭环：管理员可以通过应用视角创建项目、环境、应用、逻辑服务和环境部署配置，登记已有镜像，并在 Gate 0B 通过后发布到 Docker 单机。V0.1 允许短暂停机，但发布失败必须自动尝试恢复旧容器，并在 UI 明确标注不建议用于生产无损发布。

## 1.1 Goal 模式执行入口

如果使用 Codex Goal 模式推进阶段 1，应直接使用 [阶段1 Goal 模式提示词模板](./阶段1Goal模式提示词模板.md)。该模板要求 Codex 自动判断下一批次，每批实现、测试通过并提交中文 commit 后再进入下一批，同时维护 `docs/阶段1实施进度.md` 作为持续开发证据。

## 3. 分批方案

### 3.1 批次 1：文档基线与 CR 收口

目标：把阶段 1 的开工边界、Gate 拆分和评审结论固化到 docs，避免后续开发误把 Docker 执行链路提前纳入。

范围：

- 新增需求评审结论文档。
- 新增阶段 1 分批实施方案。
- 修复设计文档和 PRD 中 CR 指出的 Switch 参数、权限口径、成功字段清单、健康结果定义、Spike 表述等残留问题。

不做：

- 不新增后端模型。
- 不新增 API。
- 不实现 Docker 发布执行器。

依赖：已完成产品 CR 与技术 CR，Gate 0A 可通过。

交付物：

- `docs/需求评审结论.md`
- `docs/阶段1分批实施方案.md`
- PRD 与阶段 0 设计稿的小范围口径修正。

验收标准：

- Gate 0A / Gate 0B 边界在文档中无歧义。
- 文档明确批次 1 到批次 5 可先行，批次 6 到批次 7 必须等待 Gate 0B。
- 文档保留“不得提前实现 Docker 发布执行器”的红线。

### 3.2 批次 2：后端核心模型与 dataservice

目标：建立 V0.1 控制平面需要的持久化模型和数据服务，让 CRUD API 和发布控制面有稳定基础。

范围：

- 新增 Project、PlatformEnvironment、Application、ServiceDefinition、ServiceDeployment、Artifact、Release、ReleaseStep、ReleaseLock 等模型。
- 新增 RuntimeRef、DesiredSpec、HealthCheckResult、GatewaySnapshot、ConfigSnapshot 等嵌套结构。
- 接入 BoltDB dataservice、事务 StoreTx、Export/Import。
- 补齐默认值、枚举和最小校验。

不做：

- 不调用 Docker API。
- 不实现发布 worker。
- 不实现前端页面。

依赖：批次 1 完成。

交付物：

- 平台模型定义。
- 平台 dataservice。
- 模型与 dataservice 单元测试。

验收标准：

- 核心模型可创建、读取、更新、归档。
- bucket CRUD 和事务读写测试通过。
- 默认值符合 V0.1：`RuntimeDriver=docker-container`、`Replicas=1`、`Strategy=replace`。

### 3.3 批次 3：平台 CRUD API 与管理员权限

目标：提供项目、环境、应用、逻辑服务和环境部署配置的管理员 API。

范围：

- 新增 `/api/platform` handler 并接入 API server。
- 实现 Project / Environment / Application / ServiceDefinition / ServiceDeployment CRUD。
- 所有 `/api/platform` 业务接口使用管理员访问限制。
- 使用统一错误结构和 reason。

不做：

- 不实现 Release 执行。
- 不实现 Artifact 构建或镜像导入。
- 不开放项目管理员、开发者或只读观察者访问。

依赖：批次 2 完成。

交付物：

- `/api/platform` CRUD API。
- 管理员鉴权测试。
- CRUD handler 测试。

验收标准：

- 管理员可以完成项目链路创建。
- 非管理员访问平台业务接口返回拒绝。
- 更新接口支持资源版本或等价并发保护策略。

### 3.4 批次 4：Artifact 与 Release 控制平面

目标：完成已有镜像制品登记和 Release 控制平面框架，为后续 Docker 执行器接入留出稳定契约。

范围：

- 实现 Artifact `image-reference` 登记、列表、详情和归档。
- 实现 Release 状态机、合法迁移校验、ReleaseStep、ReleaseLock。
- 实现部署前 validate API。
- 实现 Idempotency-Key payload hash 比对。
- Gate 0B 通过前，`POST /api/platform/releases` 不触发 Docker，返回 `PLATFORM_UNSUPPORTED_OPERATION`，reason=`GATE_0B_REQUIRED`。

不做：

- 不启动后台 Docker worker。
- 不创建 candidate 容器。
- 不拉取镜像、不解析 digest。

依赖：批次 3 完成。

交付物：

- Artifact image-reference API。
- Release 控制平面 API。
- 状态机、幂等、并发锁测试。

验收标准：

- 相同幂等键和相同 payload 返回同一结果。
- 相同幂等键但 payload 不同返回 `PLATFORM_IDEMPOTENCY_PAYLOAD_MISMATCH`。
- 同一 ServiceDeployment 进行中发布被拒绝或复用幂等结果。
- Gate 0B 前真实发布被明确阻断。

### 3.5 批次 5：前端页面骨架与部署向导

目标：让管理员可以从应用视角进入平台页面，完成模型和向导数据录入，但不触发真实 Docker 发布。

范围：

- 接入 App Delivery 侧边栏与 ui-router / React r2a 页面。
- 实现项目、应用、服务、制品、发布记录页面骨架。
- 实现部署向导骨架：基本信息、已有镜像、镜像与 registry、端口与健康验证、环境变量、发布策略、校验结果、确认。
- Gate 0B 前禁用真实发布入口或展示阻断提示。
- 页面明确展示 V0.1 不建议用于生产无损发布。

不做：

- 不实现实时日志 WebSocket。
- 不实现真实部署进度轮询之外的 Docker 运行态。
- 不实现完整 RBAC 页面。

依赖：批次 3 可支撑基础页面；批次 4 可支撑 Artifact / Release 骨架。

交付物：

- 平台导航入口。
- 页面骨架和部署向导骨架。
- 前端 API client / query hooks。

验收标准：

- `pnpm typecheck` 通过。
- 中文和英文文案齐全。
- 空状态、无权限、Gate 0B 阻断、生产风险提示可见。
- 长镜像名、SHA256、版本号不破坏布局。

### 3.6 批次 6：Gate 0B Spike 与 Docker 执行器

目标：在 Spike 验证通过后，实现 V0.1 Docker 单机真实发布执行链路。

范围：

- 完成 Docker/Agent candidate 技术 Spike 并回填设计或 ADR。
- 实现 RuntimeDriver / ContainerAdapter / SingleTargetExecutor。
- 覆盖本地 Docker socket、容器化 Portainer、本地 Agent、远程 Agent、随机端口探测、版本化容器命名、私有镜像认证。
- 实现 candidate 启动验证、正式容器切换、旧容器恢复。

不做：

- 不实现多 Docker 主机。
- 不实现中心 Nginx 网关。
- 不实现人工历史版本回滚。

依赖：Gate 0B 通过；批次 4 的 Release 控制平面完成。

交付物：

- Spike 结论文档。
- Docker RuntimeDriver 和执行器。
- Docker 发布链路测试。

验收标准：

- 公开镜像和私有镜像可部署到 Docker 单机。
- 端口冲突、镜像拉取失败、健康检查失败有明确 reason。
- 失败时旧容器不受影响或被自动恢复。

### 3.7 批次 7：运行状态、日志、恢复与阶段 1 验收

目标：补齐 V0.1 技术预览闭环的诊断、恢复和最终验收能力。

范围：

- 实现服务状态、日志、RuntimeRef 展示接口。
- 实现 `runtime-missing` 提示。
- 实现 `recovery-failed`、`interrupted`、人工 `resolve`、恢复重试和孤儿资源清理。
- 补齐最小平台审计：发布创建、成功、失败、恢复失败、人工处置。
- 完成阶段 1 验收用例。

不做：

- 不开放阶段 2 的人工历史版本回滚。
- 不扩展 V1.0 项目级 RBAC。
- 不承诺生产级无损发布。

依赖：批次 6 完成。

交付物：

- 状态和日志 API。
- 恢复与人工处置 API。
- 最小审计落库。
- 阶段 1 验收记录。

验收标准：

- 阶段 0 设计文档第 13 章阶段 1 验收用例通过。
- 外部删除容器后服务详情显示运行资源丢失。
- 恢复失败继续持锁，直到管理员处理。
- 相关 Go 测试、前端类型检查和手工验收通过。

## 4. 执行红线

- Gate 0B 通过前，不得实现 Docker 发布执行器正式代码。
- Gate 0B 通过前，不得创建真实 candidate 容器、停止正式容器或执行端口切换。
- V0.1 所有 `/api/platform` 业务接口均限制管理员访问，包括读取接口。
- V0.1 不承诺生产级无损发布，生产环境部署必须展示短暂停机和不建议生产使用的提示。
- 阶段 1 不实现 Git 集成、源码构建、内置 registry、Kubernetes 部署、多主机、中心 Nginx 网关、完整 RBAC、人工历史版本回滚。

## 5. 验证策略

- 批次 1：检查 docs diff，确认 Gate 和 CR 口径一致。
- 批次 2：运行平台模型和 dataservice Go 单测。
- 批次 3：运行平台 handler Go 单测，覆盖管理员和非管理员访问。
- 批次 4：运行 Release 状态机、幂等和锁测试。
- 批次 5：运行 `pnpm typecheck`，手工检查中英文、明暗主题、空态和 Gate 0B 阻断。
- 批次 6：运行 Docker 执行器相关 Go 测试，手工验证公开镜像、私有镜像、端口冲突、健康失败。
- 批次 7：完成阶段 1 验收用例，记录恢复失败、运行资源丢失和人工处置路径。
